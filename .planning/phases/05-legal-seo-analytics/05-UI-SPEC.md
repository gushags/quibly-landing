# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5 (Legal + SEO + Analytics). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase character:** Mostly non-visual surface area (route handlers, metadata, file-convention emitters, server-side analytics). Three visible UI surfaces: `/privacy` page, `/terms` page, in-form consent + reassurance microcopy beneath the existing waitlist form button, plus one rendered raster surface — the `app/opengraph-image.tsx` 1200×630 social card. All surfaces inherit the locked Phase 1 brand tokens; this contract narrows those tokens to the specific decisions Phase 5 makes.

## Spacing Scale

Declared values (all multiples of 4, inherits Tailwind v4 + Phase 2 conventions):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `mb-1`) | Inline gaps inside list items |
| sm | 8px (`mb-2`, `gap-2`) | Date subtitle below H1, list-item gap |
| md | 16px (`mb-4`, `space-y-4`, `px-4`) | Default paragraph rhythm inside legal sections |
| lg | 24px (`px-6`, `gap-6`) | Page horizontal padding on mobile, microcopy block stack |
| xl | 32px (`mb-8`) | Spacing between consent microcopy block and form button |
| 2xl | 40px (`mb-10`) | Spacing between top-level sections inside `/privacy` and `/terms` (matches marketing-app pattern verbatim) |
| 3xl | 64px (`py-16`) | Vertical page padding for legal pages (top + bottom) |

**Exceptions:**
- `mb-10` (40px) is the section-break value used by marketing-app's privacy page and is preserved here for visual parity. Falls between `xl` (32) and `2xl` (48) on the canonical 8-point ladder but lands on the 4-pt grid; permitted.
- Touch targets: all anchors in legal-page prose remain inline `<a>` elements (no enforced 48px height). The footer privacy/terms links already meet ≥48px (Phase 2 D-32, locked) — Phase 5 does NOT alter the footer.
- Consent microcopy beneath the form button: stacks as two short lines with `text-xs` (12px) leading-snug; spaced 4px apart (`gap-1`).

## Typography

Phase 5 uses exactly these roles. All other text on the existing landing surface is locked by Phase 2/3 and unchanged.

| Role | Size | Weight | Line Height | Family | Usage |
|------|------|--------|-------------|--------|-------|
| Page H1 (legal) | 36px (`text-4xl`) | 700 (bold) | 1.1 (`leading-tight` default) | Quicksand (`font-heading`) | "Privacy Policy" / "Terms" page titles |
| Section H2 (legal) | 20px (`text-xl`) | 600 (semibold) | 1.4 (default) | Quicksand (`font-heading`) | "Information We Collect", "How We Use It", etc. |
| Body (legal) | 16px (`text-base`) | 400 (regular) | 1.625 (`leading-relaxed`) | Figtree (`font-sans`, default) | Prose paragraphs, list items |
| Microcopy | 12px (`text-xs`) | 400 (regular) | 1.5 (`leading-normal` default) | Figtree | Date subtitle ("Last updated: April 29, 2026"), consent + reassurance copy under form button |

**Weight contract:** exactly two weights — 400 (regular) for body/microcopy, 700 (bold) for headings. Strong emphasis inside legal prose uses semantic `<strong>` which renders 600 (semibold) by default in Tailwind — permitted as an inline-emphasis exception, not a third weight tier.

**OG image typography (`app/opengraph-image.tsx`, 1200×630):**

| Element | Size | Weight | Family |
|---------|------|--------|--------|
| Tagline | 64px | 700 (bold) | Quicksand (TTF/OTF binary loaded into `ImageResponse`) |
| Wordmark `useQuibly.com` | 28px | 500 (medium) | Figtree (TTF/OTF binary) |

D-11 binds the OG fonts to the same families as the on-page H1; recipient sees the same typographic voice in the social preview as on the landing page.

## Color

Inherits the Phase 1 brand-token contract verbatim from `app/globals.css`. Phase 5 surfaces use this restricted subset:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` = `oklch(1 0 0)` (white) | Page surface for `/privacy` and `/terms`, microcopy backdrop, OG image right ~60% panel |
| Secondary (30%) | `--muted-foreground` = `oklch(0.556 0 0)` (~mid-gray) on `--background` | Body prose paragraphs in legal pages, microcopy, "Last updated" date subtitle |
| Accent (10%) | `--primary` = `oklch(0.6002 0.1038 184.704)` (Quibly teal) | (1) Inline `<a>` anchor color in legal prose, (2) link color in consent microcopy ("Privacy Policy" + "Terms"), (3) OG image left ~40% gradient panel + mascot fill |
| Destructive | `--destructive` = `oklch(0.577 0.245 27.325)` | NOT used in Phase 5 surfaces (no destructive actions in this phase) |

**Accent reserved for:**
1. Inline anchor link color (`text-primary`) inside `/privacy` and `/terms` prose
2. The two inline anchor links inside the consent microcopy under the form ("Privacy Policy", "Terms")
3. The teal-gradient panel + the white-on-teal Quibs mascot inside `app/opengraph-image.tsx`

Accent is **NOT** applied to:
- Section H2 headings on legal pages (foreground, not teal)
- Page H1 (foreground)
- Any standalone button, badge, or callout (Phase 5 introduces none)

**Dark mode:** Out of scope. Phase 1 D-19 / CLAUDE.md "What NOT to Use" — no `next-themes`, white-dominant only.

## Visible Surfaces & Interaction Contract

### 1. `/privacy` page (`app/(legal)/privacy/page.tsx` or `app/privacy/page.tsx` — CD-01)

- **Layout:** centered single-column container, `max-w-3xl mx-auto px-6 py-16` (matches marketing-app pattern verbatim)
- **Sections (in order):** Introduction → Information We Collect → How We Use It → Cookies / Tracking (cookieless statement, folded in per Specifics §"No cookies disclosure page") → Sharing & Processors (Vercel Analytics, Vercel Speed Insights, Resend named) → Retention → Your Rights (DSAR contact) → Updates → Contact
- **Each section:** `space-y-4 mb-10`; H2 in Quicksand semibold; body paragraphs in Figtree regular `leading-relaxed`
- **Inline links:** `text-primary hover:underline` — applies to anchors back to `/`, the DSAR mailto, any external processor URL (Vercel privacy, Resend privacy)
- **Postal address:** rendered in a contact paragraph from `{env.RESEND_FROM_POSTAL_ADDRESS}` (D-04, single source of truth)
- **No interactive widgets** — pure prose page, no client JS, RSC

### 2. `/terms` page (mirror layout)

- Same container, same H1 + subtitle pattern
- Sections: Acceptance → Nature of the Waitlist → No Service Guarantees → Withdrawal → Governing Law → Contact
- Same typographic and color rules as privacy

### 3. Consent + reassurance microcopy block (under the existing form button)

- **File modified:** `components/sections/waitlist-form-section.tsx` OR `components/waitlist/waitlist-form.tsx` (planner picks insertion point — must render below the submit button, above any existing helper text)
- **Composition:** two short lines stacked vertically inside a single `<div class="mt-4 space-y-1 text-xs text-muted-foreground text-center">` block
- **Line 1 (LEGAL-07):** `No spam — unsubscribe anytime.`
- **Line 2 (LEGAL-06):** `By joining, you agree to our <a href="/privacy">Privacy Policy</a> and <a href="/terms">Terms</a>.`
- **Anchors:** `text-primary underline-offset-2 hover:underline focus-visible:underline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring rounded-sm`
- **Visibility states:** the block renders in all form states (idle, pending, success, error). When the form swaps to its in-place success state (Phase 3 POST-01), the consent block visually disappears with the form — no separate hide/show logic needed; it's a sibling of the swappable form body, not the success body.
- **Mobile reachability:** stays inside the `max-w-prose` form container; tap targets on the two anchors are inline text — they DO NOT need to meet the 48px target rule because they are not the primary form action (FORM-04 owns the primary 48px target). Inline-link tap-area exception applies, consistent with footer pattern.

### 4. `app/opengraph-image.tsx` (1200×630, `next/og` `ImageResponse`)

- **Composition (D-08):** two-column flex; left column 40% width, right column 60% width
- **Left column:** full-bleed teal gradient (`oklch(0.6002 0.1038 184.704)` → ~10% darker teal stop), Quibs Q-face mascot rendered white via inline SVG (or pre-rendered PNG asset — planner verifies `ImageResponse` SVG support during planning). Centered within column. Mascot occupies ~60% of column width.
- **Right column:** white background, vertically centered content; tagline 64px Quicksand bold; 12px gap; `useQuibly.com` 28px Figtree medium; both left-aligned with 64px left padding
- **Color tokens:** mirrors the on-page hero colorway (teal panel mimics welcome-email header strip aesthetic per D-08)
- **Verification surfaces (manual checkpoint, not Phase 5 code):** opengraph.xyz, X Card validator, LinkedIn Post Inspector — each must render the image correctly (SC #2)

### 5. `app/icon.tsx` / `app/favicon.ico` + `app/apple-touch-icon.png`

- **Visual:** Quibs Q-face derivation. White background, teal mascot fill at full bleed (or with ~8px margin if the file convention requires).
- **Sizes:** 32×32 favicon, 180×180 apple-touch-icon (Next.js file-convention defaults — planner confirms during plan).
- **Source:** `public/quibs-icon.svg` already in the repo from Phase 1.

### 6. `/sitemap.xml` and `/robots.txt`

- Not visible UI; XML/text emitted by `app/sitemap.ts` and `app/robots.ts`. No design contract beyond correct `Allow: /` rules per D-05/D-06.

### 7. Schema.org JSON-LD `<script type="application/ld+json">`

- Not visible UI; injected from `app/page.tsx` or `app/layout.tsx` per CD-02. No design contract.

### 8. Vercel `<Analytics />` + `<SpeedInsights />` mounts

## Accessibility Contract

- **Color contrast:**
  - Body text on white: `--foreground` (`oklch(0.145 0 0)`) on `--background` (`oklch(1 0 0)`) — far exceeds WCAG AA (≥7:1, AAA territory)
  - Microcopy `text-muted-foreground` (`oklch(0.556 0 0)`) on white — ratio ~4.6:1, passes WCAG AA for normal-size text but is borderline. **Mitigation:** microcopy is 12px, anchors inside the microcopy use full `text-primary` teal which retains ≥4.5:1 against white at the locked `oklch(0.6002 0.1038 184.704)` luminance.
  - OG image right panel: tagline foreground (`--foreground`) on white, identical contrast as body. OG image left panel: white mascot on teal — verified contrast ratio for the icon glyph against teal must be ≥3:1 (large graphical element).
- **Focus order:** legal-page anchor links flow in source order; consent-microcopy anchors come AFTER the submit button in the tab order (sibling-after-button placement enforces this).
- **Screen-reader landmarks:** legal pages use a single `<main>`-equivalent container; H1 → H2 hierarchy preserved; lists use semantic `<ul>` / `<ol>`.
- **Link discrimination:** all consent-microcopy anchors carry visible text + `text-primary` color + hover/focus underline — link discrimination by color + decoration both, not color alone.
