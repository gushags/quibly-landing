  <action>
    Create the directory `.github/workflows/` if it does not exist, then create `.github/workflows/lighthouse.yml` with this EXACT content (verbatim from RESEARCH.md § GitHub Actions Workflow):

    ```yaml
    # Source: treosh/lighthouse-ci-action v12 + patrickedqvist/wait-for-vercel-preview
    name: Lighthouse CI

    on:
      push:
        branches: [main]
      pull_request:
        branches: [main]

    jobs:
      lighthouse:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4

          - name: Wait for Vercel Preview
            id: vercel-preview
            uses: patrickedqvist/wait-for-vercel-preview@v1.3.1
            with:
              token: ${{ secrets.GITHUB_TOKEN }}
              max_timeout: 300
            env:
              VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}

          - name: Run Lighthouse CI
            uses: treosh/lighthouse-ci-action@v12
            with:
              urls: ${{ steps.vercel-preview.outputs.url }}
              configPath: .lighthouserc.json
              uploadArtifacts: true
              temporaryPublicStorage: true
            env:
              LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}
    ```

    Line-by-line rationale (do NOT modify any of these without a plan-level review):

    - `on: push: branches: [main]` — runs on every push to `main` (the Vercel production deploy will also trigger).
    - `on: pull_request: branches: [main]` — runs on every PR targeting `main`. This is the gate that matters for blocking merge.
    - `uses: actions/checkout@v4` — standard checkout step; required by `treosh/lighthouse-ci-action`.
    - `patrickedqvist/wait-for-vercel-preview@v1.3.1` — polls the Vercel API until the preview deploy for this commit is `READY`. Outputs `steps.vercel-preview.outputs.url`, which is the actual Vercel preview URL (e.g., `https://quibly-landing-abc123.vercel.app`). `max_timeout: 300` = 5 minutes. The `VERCEL_TOKEN` secret goes in `env:` (not `with:`) per this action's documented usage.
    - `treosh/lighthouse-ci-action@v12` — runs LHCI against the Vercel preview URL. `configPath: .lighthouserc.json` tells it to use our assertions config. `uploadArtifacts: true` uploads the HTML report as a GitHub Actions artifact (downloadable from the run page). `temporaryPublicStorage: true` also posts the report URL to a public CDN so reviewers can click directly from the PR.
    - `LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}` — optional; if the `lighthouse-ci` GitHub App is installed, this enables rich status-check annotations on PRs. Without it, the action still runs and uploads artifacts — it just doesn't annotate individual PR status checks.

    **Required secrets (NOT automated — covered in Task 4):**
    - `VERCEL_TOKEN` — must be set as a repo secret before the action can poll Vercel. Without it, `patrickedqvist/wait-for-vercel-preview` will fail with `Error: VERCEL_TOKEN is not set`.
    - `LHCI_GITHUB_APP_TOKEN` — optional. Without it, the LHCI step runs but doesn't post score annotations to the PR diff.
    - `GITHUB_TOKEN` — automatically provided by GitHub Actions; no manual setup needed.

    If `actionlint` is available in the executor's environment, run it as a quick syntax check:
    ```bash
    which actionlint && actionlint .github/workflows/lighthouse.yml || true
    ```
    (The `|| true` prevents failure if `actionlint` is not installed — it is optional tooling.)
