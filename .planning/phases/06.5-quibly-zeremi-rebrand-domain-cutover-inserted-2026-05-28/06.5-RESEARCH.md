## Summary

Phase 6.5 is a **branded sweep**, not a code-architecture change. No new dependencies, no new routes, no new Server Actions. The work decomposes into six distinct concerns: (1) typography swap (`next/font/google` Quicksand → Bree Serif), (2) asset copy and icon/favicon/OG rewire, (3) component rename (`components/quibs/` → `components/zeremi/`) with the new inline SVG ported from `marketing-app/public/brand/zeremi/src/zeremi-mark.svg`, (4) a mechanical string sweep across all remaining `Quibly`/`Quibs`/`useQuibly.com` occurrences in source and tests plus a CI guard to lock the rename, (5) Resend sender domain verification on `zeremi.app` and welcome-email update, and (6) in-place edits to the already-written Phase 6 plans `06-04-PLAN.md` and `06-05-PLAN.md` to retarget `zeremi.app` / `staging.zeremi.app`.

The codebase is fully enumerable — a complete grep audit was run and every `Quibly`/`Quibs`/`useQuibly.com`/`Quicksand` reference is catalogued in the Runtime State Inventory and Code Examples sections below. There are no hidden landmines that would surprise the executor, but there are several non-obvious surfaces that are easy to miss: the unsubscribe route's inline HTML templates (which embed `Quicksand` in a hardcoded `<link>` to fonts.googleapis.com), the `@quibly/ratelimit/*` Redis key prefixes in `lib/rate-limit.ts`, the `WORDMARK_CID = 'wordmark@quibly'` constant in `emails/WelcomeEmail.tsx`, the Satori-based `opengraph-image.tsx` which reads `public/fonts/Quicksand-Bold.woff` from disk, and the `generate-wordmark.mjs` script which renders "Quibly" in Quicksand.

The welcome email wordmark is currently a pre-rasterized PNG at `public/email/wordmark.png` (rendered by `scripts/generate-wordmark.mjs`). After the rebrand, the wordmark must be re-generated as "zeremi" in Bree Serif, which requires adapting `generate-wordmark.mjs` to use a Bree Serif font source.

**Primary recommendation:** Plan 6.5 in five waves landing on a single `rebrand/zeremi` feature branch: (1) brand tokens + font swap + asset import, (2) component rename, (3) string sweep + test updates + CI guard, (4) email/Resend domain work (manual-gated), (5) Phase 6 plan edits. Merge to main with a merge commit once all five waves are green.

### Anti-Patterns to Avoid

- **Renaming the phase directory slug:** The phase slug `06.5-quibly-zeremi-rebrand-domain-cutover-inserted-2026-05-28` must NOT be renamed. GSD INIT derived this path; renaming would orphan STATE.md continuity.
- **Activating the CI grep guard BEFORE the rename sweep is complete:** The grep guard for `Quibly|Quibs|useQuibly\.com` will cause every intermediate commit to fail CI. The guard MUST be added in a final step of the wave after all source strings are already renamed. Sequence: rename everything first, then activate the guard.
- **Touching `app/globals.css` brand tokens:** Only `--font-heading` changes. Do NOT modify any oklch color tokens, `--radius-*` scale, or sidebar/chart tokens. The teal palette is identical between Quibly and Zeremi.
- **Requesting `weight: ['700']` for Bree Serif:** Bree Serif only ships weight 400. Any other weight requested from `next/font/google` will error. [VERIFIED: Next.js font-data.json]
- **Symlinking the brand assets:** The `marketing-app` repo is separate. Assets MUST be copied (not symlinked) into `public/brand/zeremi/`.
- **Adding `?` to the CI exclude list for `.planning/`:** The grep guard must exclude `.planning/` to avoid false positives on the phase slug itself (`06.5-quibly-zeremi-...`). The pattern `--exclude-dir=.planning` is required.

## Common Pitfalls

### Pitfall 1: Activating the CI grep guard before the rename sweep is complete

**What goes wrong:** If `scripts/check-no-quibly.mjs` and the `.github/workflows/test.yml` step are committed to the rebrand branch BEFORE all Quibly strings are removed, every subsequent CI run will fail immediately, blocking other plan commits from verifying.
**Why it happens:** Natural temptation to add the guard early as a "progress check."
**How to avoid:** The grep guard commit MUST be the final Wave 3 task, after all string edits and test updates are confirmed clean locally (`node scripts/check-no-quibly.mjs` passes before the commit).
**Warning signs:** If CI fails on the grep step on the very first push after adding the guard, strings were not fully cleaned.

### Pitfall 2: Bree Serif at weight 700 in OG image

**What goes wrong:** `opengraph-image.tsx` currently loads `Quicksand-Bold.woff` (weight 700) for the OG tagline. Bree Serif ships only weight 400. Requesting weight 700 in the Satori font config silently falls back to 400 (or may cause a rendering error).
**Why it happens:** Copy-paste from existing Quicksand Bold setup.
**How to avoid:** Change OG font to weight 400 and update Satori font config accordingly. The visual difference (400 vs 700 in Bree Serif) should be reviewed — Bree Serif 400 is already bold-looking by design.
**Warning signs:** OG image renders with unexpectedly light weight, or Satori throws a "font weight not found" error.

### Pitfall 3: `app/unsubscribe/route.ts` has THREE inline HTML blocks, each with Quicksand

**What goes wrong:** The unsubscribe route returns inline HTML strings for three response states (error, success, invalid-token). Each HTML block has a `<link href="https://fonts.googleapis.com/css2?...Quicksand...">` and an `h1 { font-family: Quicksand }` in the embedded `<style>`. A simple find-and-replace on the file is fine, but a word processor-style "find next" approach might miss all three.
**Why it happens:** The three blocks are structurally identical and spaced far apart in the file (~200 lines each).
**How to avoid:** Use `sed -i '' 's/Quicksand/Bree Serif/g'` or the Edit tool with a full-file replacement strategy, then verify with `grep -c "Quicksand" app/unsubscribe/route.ts` returns 0.
**Warning signs:** `grep -n "Quicksand" app/unsubscribe/route.ts` still returns lines after the edit.

### Pitfall 4: `WORDMARK_CID = 'wordmark@quibly'` is exported and used in tests

**What goes wrong:** `WelcomeEmail.tsx` exports `WORDMARK_CID = 'wordmark@quibly'`. `app/actions/join-waitlist.ts` imports this constant. `tests/unit/join-waitlist-action.test.ts` imports it too (line 75: `WORDMARK_CID: 'wordmark@quibly'`). If you change the constant's value in `WelcomeEmail.tsx` but forget to re-run the test (or if the test hardcodes the old string), CI breaks.
**Why it happens:** The test file hardcodes the CID string in addition to importing the constant — look for `'wordmark@quibly'` in the test.
**How to avoid:** Change `WORDMARK_CID` in `WelcomeEmail.tsx` and check whether `join-waitlist-action.test.ts` has any hardcoded reference to `'wordmark@quibly'`. [VERIFIED: line 75 and 315 in `tests/unit/join-waitlist-action.test.ts` — both must be updated.]

### Pitfall 5: `app/icon.tsx` and `app/apple-icon.tsx` use ImageResponse + `readFile` to composite a background + mascot PNG

**What goes wrong:** Current `icon.tsx` reads `public/quibs-icon.png` (a bare SVG-rendered Q-face), composites it onto a teal background via ImageResponse, and emits the 32×32 favicon. After the rebrand, the simplest path is to read `zeremi-icon-square-32.png` directly (which already has the teal gradient background and white Z mark baked in). This makes the ImageResponse wrapper unnecessary — but if you keep it, you're compositing an already-square-chip PNG onto another background, which will look wrong.
**Why it happens:** Over-engineering — the brand PNGs are already fully composited with gradient background.
**How to avoid:** Replace the entire ImageResponse with a `NextResponse` that streams the pre-composited PNG bytes, OR simplify `icon.tsx` to return a minimal ImageResponse that just displays the pre-composited PNG. Alternatively, use Next.js's static icon convention: rename `zeremi-icon-square-32.png` to `icon.png` in `app/` and Next.js serves it automatically as the favicon. [ASSUMED: the static file convention removes the need for `icon.tsx` entirely — verify against Next.js App Router docs.]
**Warning signs:** Favicon looks like a teal square on a teal square, or has unexpected double-compositing artifacts.

### Pitfall 6: OG image Satori font — Bree Serif WOFF source

**What goes wrong:** Satori (the renderer behind `ImageResponse`) requires a static WOFF or TTF buffer. `next/font/google` only works at runtime for CSS; it does NOT provide a WOFF buffer for Satori. The current implementation reads `public/fonts/Quicksand-Bold.woff` from disk. After the rebrand, the executor needs a Bree Serif WOFF file.
**Why it happens:** There is no `@fontsource/bree-serif` in the current `package.json`, and Bree Serif WOFF is not in `public/fonts/`.
**How to avoid:** Either (a) add `@fontsource/bree-serif` as a dev dep and read from `node_modules/@fontsource/bree-serif/files/bree-serif-latin-400-normal.woff2` (then decompress WOFF2 → TTF via `wawoff2`, same as the wordmark script), OR (b) copy a Bree Serif WOFF file into `public/fonts/` (check if `marketing-app/public/fonts/` has one). [ASSUMED: the WOFF file path in @fontsource/bree-serif follows the `@fontsource/*` naming convention — verify before implementing.]
**Warning signs:** OG image renders with a system fallback font instead of Bree Serif.

### Pitfall 7: `zeremi-mark.svg` uses `fill="url(#g)"` with a gradient `<defs>` block — NOT `fill="currentColor"`

**What goes wrong:** The raw SVG at `marketing-app/public/brand/zeremi/src/zeremi-mark.svg` uses `fill="url(#g)"` with a `linearGradient` defined in `<defs>`. If you inline this SVG verbatim into `zeremi-icon.tsx`, the gradient ID `g` may conflict with other SVGs on the page, and the `fill="currentColor"` pattern used by `QuibsIcon` (and expected by `ZeremiAvatar`'s Tailwind text utilities) won't work.
**Why it happens:** Source SVG uses self-contained gradient; the React component pattern requires `fill="currentColor"` for Tailwind text-color utilities to drive the icon color.
**How to avoid:** Strip the `<defs>` gradient block and replace `fill="url(#g)"` on the inner `<g>` with `fill="currentColor"`. This is the same transformation done for `QuibsIcon`. The color is then driven by the parent container's `text-white` class. [VERIFIED: `quibs-icon.tsx` uses this pattern; the Z mark SVG path data (two paths: the Z letter + two dots) was verified from the source file.]
