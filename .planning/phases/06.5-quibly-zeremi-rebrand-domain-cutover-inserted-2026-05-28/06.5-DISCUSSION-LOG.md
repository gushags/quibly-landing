## Z-mark rendering in hero

### Q1 (clarified): How should the Z mark render in the hero?

The user redirected the option set to "mirror exactly how Quibs was done." Reviewed the existing Quibs three-component pattern (`QuibsIcon` inline SVG, `QuibsAvatar` sized wrapper with `SIZE_CONFIG` + `inverted` prop, `HeroMascot` 88×88 rounded-3xl teal-gradient section-local container) and confirmed the Zeremi parallel:

- `components/zeremi/zeremi-icon.tsx` — inline SVG from `marketing-app/public/brand/zeremi/src/zeremi-mark.svg` (56×88 Z glyph), `fill="currentColor"`, aria-hidden, prop shape `{ className?, width?, height? }`
- `components/zeremi/zeremi-avatar.tsx` — same `SIZE_CONFIG` (message / header / fab), same gradient container, `inverted` prop preserved
- `components/sections/hero-mascot.tsx` — keeps filename and 88×88 gradient wrapper; renders `<ZeremiIcon width={36} height={56} />` (56:88 aspect)

**User's choice:** Mirror the Quibs pattern exactly (inline SVG + sized avatar wrapper + section-local hero container).
**Notes:** No HTTP request, RSC-payload sized, color flexibility via `currentColor`, no LCP risk. The Quibs `HeroMascot` is already static (no keyframe animation), so the brand-decisions note's "delete the animation" guidance is a no-op for this repo.
