    Write `lib/unsubscribe-token.ts`. Encode `email` directly (NOT contactId) per PATTERNS.md and RESEARCH "Simpler alternative" — this avoids a Resend API lookup in Plan 06's unsubscribe route. The HMAC signing key is `env.RESEND_WEBHOOK_SECRET` (reused per CD-02 — no separate `UNSUBSCRIBE_SECRET` env var needed).

    ```typescript
    import 'server-only'
    import { env } from '@/lib/env'

    /**
     * Phase 4 — RFC 8058 one-click unsubscribe token (CD-02).
     *
     * Encodes email (not contactId) so the unsubscribe route can call
     * `resend.contacts.update({ email, unsubscribed: true })` directly with no
     * Resend API lookup. Token shape: `${base64url(email)}.${base64url(hmac_sha256)}`.
     *
     * Signing key: env.RESEND_WEBHOOK_SECRET (reused per CD-02 — keeps env surface small).
     *
     * Verification is timing-safe (constant-time XOR loop over the full byte length).
     */

    const encoder = new TextEncoder()

    let cachedKey: CryptoKey | null = null

    async function getKey(): Promise<CryptoKey> {
      if (cachedKey) return cachedKey
      cachedKey = await crypto.subtle.importKey(
        'raw',
        encoder.encode(env.RESEND_WEBHOOK_SECRET),
        { name: 'HMAC', hash: 'SHA-256' },
        false,
        ['sign', 'verify'],
      )
      return cachedKey
    }

    export async function generateToken(email: string): Promise<string> {
      const key = await getKey()
      const sig = await crypto.subtle.sign('HMAC', key, encoder.encode(email))
      const hmac = Buffer.from(sig).toString('base64url')
      const encodedEmail = Buffer.from(email).toString('base64url')
      return `${encodedEmail}.${hmac}`
    }

    /**
     * Returns the original email if the token is valid; null otherwise.
     * Timing-safe — does not short-circuit on first mismatched byte.
     */
    export async function verifyToken(token: string): Promise<string | null> {
      if (!token) return null
      const parts = token.split('.')
      if (parts.length !== 2) return null
      const [encodedEmail, hmacB64] = parts
      if (!encodedEmail || !hmacB64) return null

      let email: string
      try {
        email = Buffer.from(encodedEmail, 'base64url').toString('utf-8')
      } catch {
        return null
      }
      if (!email) return null

      const expected = await generateToken(email)
      const expectedHmac = expected.split('.')[1]
      if (!expectedHmac) return null

      const a = Buffer.from(expectedHmac, 'base64url')
      const b = Buffer.from(hmacB64, 'base64url')
      if (a.length !== b.length) return null

      let diff = 0
      for (let i = 0; i < a.length; i++) diff |= a[i] ^ b[i]
      return diff === 0 ? email : null
    }
    ```

    Notes:

    - `crypto.subtle` is available globally on Node 18+ (verified Node 24.7 in env audit).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email client → app/unsubscribe POST | Untrusted token from external HTTP request must be HMAC-verified before any state change |
| token bytes → HMAC compare | Tampered tokens must not unsubscribe arbitrary contacts |
| `track()` properties → server logs | Properties may include user-supplied email; logged structurally without sanitization in Phase 4 (acceptable since logs are private) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | `verifyToken` | mitigate | HMAC-SHA256 over `RESEND_WEBHOOK_SECRET` (256-bit key strength); timing-safe constant-time compare via XOR loop (`diff |= a[i] ^ b[i]`) over full HMAC byte length; `Buffer.from(.., 'base64url')` decode wrapped in try/catch so malformed tokens return null instead of throwing. |
| T-04-07 | Spoofing | One-click unsubscribe | mitigate | Token encodes email (not raw contactId); attacker without `RESEND_WEBHOOK_SECRET` cannot forge a valid HMAC for an arbitrary email. Secret is server-only (`import 'server-only'`) and Phase 1 gitleaks rule blocks `whsec_*` from commits. |
| T-04-08 | Information Disclosure | Token URL | accept | Email is base64url-encoded in the URL — readable to anyone with link access. Acceptable risk: the only valid recipient of the URL is the email's actual owner (delivered via Resend); URL-leaked emails are not a meaningful threat for a public waitlist. |
| T-04-09 | Information Disclosure | `lib/analytics.ts` shim | accept | Phase 4 logs to stdout via `console.log('[analytics]', ...)` — Vercel serverless logs are access-controlled. Phase 5 swaps to `@vercel/analytics/server`. No PII handling change required for shim. |
| T-04-10 | Denial of Service | HMAC computation per signup | accept | One HMAC-SHA256 per signup is sub-millisecond; `cachedKey` avoids re-import; no DoS exposure. |
| T-04-11 | Tampering | TrackEvent string union | mitigate | TypeScript-level enforcement — adding a new event without updating the union is a compile error. `npm run check` blocks PR merge. |
</threat_model>
