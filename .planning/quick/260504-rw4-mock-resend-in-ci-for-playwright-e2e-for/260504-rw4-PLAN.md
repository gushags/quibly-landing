<objective>
Unblock the 4 failing Playwright e2e tests in CI by introducing a single env-gated
mock for the Resend SDK at `lib/resend.ts`. After 260504-r7b fixed env drift,
Playwright now actually executes the form-submit tests against the booted Next
server — but the form's Server Action calls
`resend.contacts.get({ audienceId, email })` against the live Resend API with the
stub key `re_test_stub`, which returns `400: API key is invalid`. The action
returns an error envelope, the success-state assertions fail.

Solution: branch on `process.env.RESEND_MOCK === '1'` at module load. When set,
export a hand-rolled mock that satisfies the four call sites
(`contacts.get`, `contacts.create`, `contacts.update`, `emails.send`) plus
`webhooks.verify` for completeness, cast `as unknown as Resend` so types stay
identical at every consumer. Wire `RESEND_MOCK: '1'` into the
`.github/workflows/test.yml` "Run Playwright tests" env block ONLY (not the
build step — keep build path identical to production).

Purpose: green Playwright CI without standing up a Resend test account, without
touching application logic, without touching test files, and without changing
the production code path (env var is unset in Vercel → `new Resend(...)` runs
exactly as today).

Output: `lib/resend.ts` env-gated; CI workflow injects `RESEND_MOCK=1` for the
playwright job's test step.
</objective>

   `export const resend = (process.env.RESEND_MOCK === '1' ? mockResend : new Resend(env.RESEND_API_KEY)) as unknown as Resend`
